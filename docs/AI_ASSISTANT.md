# Conversational assistant / SQL RAG

`POST /api/chat.php` validates method, CSRF, JSON shape/size and message length. A shared MySQL limiter reserves session/IP capacity, then PHP derives category, budget and search terms and executes prepared SQL. Up to 12 relevant rows are sent to Gemini with the last eight actual conversation messages, previous filters and selected IDs. One model request generates both natural Hebrew prose and up to four product IDs. No model-generated SQL, external tools or vector database is involved.

The default lightweight model is configurable. A 25-second total cURL deadline (configurable 5–28), 8-second connect deadline and 35-second client deadline replace the previous short connection window and two model requests. The pending session marker expires after 35 seconds. PHP releases the session lock during the external call. There are no automatic retries, which avoids silently consuming extra quota. A failed message remains in the input for an explicit retry; provider failures are not retained as conversational facts. A response lost after server completion can be recovered through history on reopening/navigation, but there is no exactly-once network delivery guarantee.

Gemini returns structured `segments`, `product_ids` and `compare`. General segments explain technical concepts. Catalog segments use tokens such as `{{p:2:name}}`, `{{p:2:price}}`, `{{p:2:short_description}}`, `{{p:2:stock}}`. PHP validates IDs and allowed fields, rejects literal numeric/currency catalog claims and links, and resolves tokens from SQL results. An unsafe general price/store aside is omitted; an entirely invalid reply fails safely. Product cards and comparisons always use actual database fields and locally constructed product links. A fresh SQL read checks catalog facts after network latency and rejects stale answers if they changed.

This factual rendering does not make language-model reasoning infallible. Qualitative suitability advice and general knowledge remain model-generated; the prompt explicitly requires acknowledging missing CPU/GPU/other specifications. Catalog descriptions themselves must be accurate. Missing specifications are not filled from the model's memory. Visitors should ask for clarification rather than treat a recommendation as a benchmark result.

Retrieval uses deterministic Hebrew/English category aliases, explicit numeric budgets/ranges and distinctive brand terms, with escaped LIKE and a budget/category-preserving fallback. This is intentionally sized for the supplied 12-product catalog. Unusual phrasing, ambiguous category references and a substantially larger catalog can reduce recall; extend retrieval and its tests before growing the store. General questions still use one Gemini call. No account, address, contact or order records are sent to Google. User-entered chat messages and public catalog descriptions are sent; the UI warns against entering personal information.

Context is session-local, expires after 30 minutes, and is cleared on login/logout/reset. No browser localStorage is used. The client restores prior text bubbles on navigation, renders with `textContent`, supports keyboard Enter/Escape, and keeps RTL product comparison tables horizontally scrollable inside the panel.

Limits default to five messages/session/minute, ten/IP/minute, ten model calls globally/minute, 100/day. Global limits count failed calls too. Counters store HMAC scope hashes and expire through bounded cleanup. Tune limits down to your Google project quota. Fixed windows permit a burst across boundaries and IP limits can affect shared networks. Do not trust arbitrary forwarding headers to identify clients.
